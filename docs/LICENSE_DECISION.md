# GitHub 许可证选择

当前仓库尚未添加根目录 `LICENSE`。在选择前，不应对外宣称这是可自由商用的开源项目。

## 推荐选择

如果目标是“公开核心代码获得信任，同时销售部署、连接器、规则配置和持续服务”，建议优先评估 **AGPL-3.0**。使用者如果修改代码并通过网络提供服务，通常需要向服务用户提供相应源码；商业客户如不接受，可另签商业许可证。这是双许可证路线的常见基础，但正式使用前应让熟悉软件许可的专业人士核对你的业务安排。

如果近期重点是保护代码和寻找首批付费客户，先使用 **Private GitHub 仓库且不添加开源许可证** 更直接。没有许可证不等于禁止他人看到代码，也不适合作为公开协作项目；它只表示默认版权规则适用。

宽松的 MIT 或 Apache-2.0 适合追求最大复用，但他人可以在满足许可证条件后用于商业产品，难以仅靠核心代码控制商业复制。Apache-2.0 还包含明确的专利许可条款。

## 发布前确认

1. 代码、场景配置和文档均有权公开。
2. 第三方依赖许可证与选择的项目许可证兼容。
3. 确认开源核心和付费服务的边界。
4. 将选定许可证全文保存为根目录 `LICENSE`，再把仓库设为 Public。
