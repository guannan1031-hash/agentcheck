# GitHub 许可证选择（v2）

**决策（2026-10-08）：根目录 `LICENSE` 使用 GPL-3.0（GNU General Public License v3）。**

## 为什么从 MIT 换成 GPL-3.0

| | MIT（原） | GPL-3.0（现） |
| --- | --- | --- |
| 商用 | ✅ 允许 | ✅ 允许 |
| 闭源衍生 | ✅ 允许（别人可拿代码做闭源产品卖钱） | ❌ 不允许（衍生品必须同样以 GPL 开源） |
| 防"无缘无故商用化" | 无法防 | **可防闭源商用** |
| 开源大赛资格 | ✅ OSI 批准 | ✅ OSI 批准 |

**结论**：参赛项目要保持"开源"资格，不能完全禁止商用（CC-BY-NC 等非 OSI 协议不符合开源定义）；GPL-3.0 是"允许使用与商用、但强制开源衍生品"的平衡解——别人可以用、可以改进，但拿我们的架构做闭源产品就必须开源其改动，防止白嫖商用。

## 为什么不是 AGPL-3.0

AGPL-3.0 更强：连通过 SaaS/云服务提供都强制开源。本项目短期内面向私有化部署与规则包市场，AGPL 的"网络 Copyleft"条款会明显降低企业采用意愿、影响开源生态评分；若未来主打 SaaS 场景，可再升级 AGPL（许可证头部声明替换即可）。

3. 开源核心与付费服务边界：核心引擎 GPL 开源；行业规则包 / 私有化部署支持为商业服务 ✅
4. 已保存 GPL-3.0 全文为根目录 `LICENSE`，仓库已 Public ✅
