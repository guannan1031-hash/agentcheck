# 全场景 P0 实现说明 V1.4

日期：2026-09-14。状态：本地开发完成并通过自动测试；真实平台接入、商家规则确认和真实客户发送未开展。

## 目标用户与业务价值

客服使用全场景中心识别问题和补齐事实；主管确认规则与人工边界；运营、供应链、仓储物流、财务和质量查看对应职责。P0的业务价值是让218个场景有统一入口和安全兜底，减少漏分诊、重复追问和未经授权的承诺。

## 已实现

- 从源表派生218条稳定ID、业务域、来源坐标、必需事实、风险、建议责任部门和开发批次；运行时不读取源Excel。
- 场景中心支持搜索、业务域过滤、合成案件创建、事实勾选和多轮追加。
- 精确场景名或人工所选场景可进入P0判断；弱信号、冲突场景和未知场景不强行分类。
- 缺事实时返回补证建议；事实齐全但业务规则未确认时停在“待业务规则确认”。
- 新一轮出现食品安全、赔付、退款、投诉、隐私或指令注入信号时，旧的低风险判断失效并转人工。
- 场景案件、版本和判断历史保存到SQLite/PostgreSQL兼容存储；重复请求幂等，旧版本更新被拒绝。
- 新增“质量”登录角色，可查看全场景配置和接收质量工单；不能冒充客服创建案件。
- 客服可按场景提交是否发生、近30天数量、当前岗位步骤、使用系统和规则疑点；主管可确认、退回或标记当前试点不适用。
- 业务反馈和主管确认使用版本校验、幂等请求与审计；确认的是业务资料，不会自动发布规则或开启真实动作。
- 测试界面可关闭人工场景提示，单独观察自然语言自动识别；未知、歧义和多意图继续走人工分诊。
- 每个测试案件版本可由客服标记“正确 / 错误 / 不确定”；错误样本必须选择期望场景，形成可统计、可回查的标注数据。

## 输入与处理流程

输入仅限合成或已脱敏文本、人工所选场景、已确认事实标记和请求ID。处理顺序为：隐私检查 → 场景识别 → 上下文合并 → 风险复核 → 必需事实检查 → 业务规则门禁 → 保存版本与审计。

当前的人工场景选择会显示为 `user_selected`，不能当作模型准确识别。精确标题基准只验证218条配置和接口没有断线，不代表自然语言泛化效果。

## 风险与转人工

任何未知/歧义场景、高风险场景、资金/赔付/投诉/法律/健康信号都进入人工分诊。规则尚未逐项确认，所以事实齐全也不进入真实执行。客户手机号、地址、订单原文、身份信息、病历、Token和Cookie不得输入或保存。
