一、背景与痛点

企业正在大规模把客服、运营、售后等业务交给 AI Agent，但 Agent 输出不可信成为规模化上线的第一道门槛：答非所问、幻觉编造、隐私泄露、承诺赔付、该转人工却自动答复……一次失控就可能引发投诉、赔付甚至监管风险。

  • 抽检漏检：人工抽检覆盖率通常 <5%，漏检风险长期存在；
  • 平台质检锁定平台：抖音飞鸽、淘宝等平台自带质检只能覆盖自家渠道，无法统一跨平台口径；
  • 规则与模型分离难：质检规则散落在各业务代码里，换行业等于重写；
  • 成本高：用通用大模型逐条质检，单条成本与延迟都无法支撑全量。

二、解决方案：统一质量门禁

AgentCheck 是引擎通用、规则可插拔、裁判可替换的 Agent 输出质检工具：对任何 Agent 的每条输出，先由确定性规则层毫秒级拦截（路由/隐私/合规/完整性），再由毫秒级裁判 Jev做语义级快判，低置信判定自动升级人工复核，全程输出证据链。

核心能力

  1. 毫秒级全量质检：确定性规则 + Jev（System One 决策模型，70–500ms 判定、只判断不生成），从"抽检"升级为"全量"，实测批量单条平均 0.4ms（纯规则通道）；
  2. 可插拔规则包：电商客服包（218 场景基准）与汽车金融包共用同一引擎，仅替换 JSON 规则定义，跨行业零重写；
  3. 双裁判降级架构：Jev 不可用时自动降级 LLM（DeepSeek/智谱），未配置裁判时规则层兜底，永不静默放过；
  4. 置信度分级升级：critical 违规或低置信判定 → 自动进入人工复核队列，可审计可整改；
  5. 证据链可解释：每条判定附带命中词/依据与置信度，质检报告可追溯、可用于整改闭环。

关键设计决策

  • 为什么用 Jev：通用 LLM 逐条判定成本与延迟无法支撑全量质检；Jev 只判断不生成，返回概率与置信度，天然适合"输出是否合规"的判定任务，官方实测相比 LLM 判定快约 7 倍、省约 30% 成本（论文：JEV-as-a-Judge: Accept When Confident, Escalate When Unsure）；
  • 为什么保留规则层：确定性正则零成本、零延迟、可审计，拦截高置信违规（隐私泄露、承诺赔付）绝不错放，同时降低裁判调用量；
  • 为什么接口化裁判：Jev 国内可用性尚待验证，接口化 + 降级链保证任何环境都可运行、都有产出；
  • 为什么规则包 JSON 化：业务规则与引擎代码分离，行业扩展（电商→汽车金融→医疗→政务）只写配置不写代码，可版本化、可评审；
  • 为什么做闭环与数据反哺：质检不是终点而是数据生产入口——违规证据反哺规则包（pattern 驱动加入即生效）、知识库（待发布）、培训课件与客户分析，让 AI 客服随质检持续进化，形成企业级质量飞轮。

四、应用场景与演示

场景 1：电商客服质检（内置 218 场景基准）

基于 218 个业务场景（退换退款/食品安全/订单物流等 10 个域）与 93KB 基准对话集，对 Agent 每条输出执行质检。演示样本：客户投诉"食品发霉要求退款赔偿"，Agent 若自动回复并承诺全额退款 → 路由/合规/隐私三通道全红，0.4–1.7ms 判定违规并升级人工；Agent 若正确转人工 → 全通道通过。

场景 2：汽车金融客服（可插拔规则包实例）

同一引擎加载 汽车金融规则包：催收合规（禁非允许时段联系、禁向第三方泄露债务）、征信红线（禁承诺消除征信）、减免承诺（禁承诺减免本金/利息）、监管投诉升级。演示"减免利息 + 不上征信"违规输出 → 立即拦截。

场景 3：批量全量质检

一次性质检 40 条样本（20 违规 + 20 合规）：全部正确分类，平均 0.4ms/条，违规 100% 检出并进入人工复核队列 —— 支撑"从抽检到全量"的质检升级。

场景 4：质检反馈闭环 + 数据反哺（持续进化）

质检发现违规后，一键生成整改建议（路由策略 / 隐私规则 / 合规规则 / 知识补全 / 提示词优化）→ 应用整改真实写入规则包（带 pattern 的新规则加入即生效，规则包版本随整改自动递增 0.1→0.3）→ 重检验证 fail→pass（实测得分 0.00→1.00）→ 整改样本登记回归用例防复发，全程留痕可审计。

同时质检数据反哺业务：人工培训课件（按违规维度聚合典型案例与正确话术）、客户画像（218 场景聚合诉求域/风险/高频词）、复购节奏（质检关联客户订单 → 复购率与周期分析，演示用脱敏示例数据）。

演示视频与代码仓库
